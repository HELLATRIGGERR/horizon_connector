# horizon-connect: игра с друзьями для обычного Minecraft

*[English](horizon-connect.md) · Русский*

[Play with Friends](play-with-friends.md) передаёт протокол vanilla без изменений через зашифрованный туннель
между двумя локальными портами, но открыть этот туннель умеет только сам Horizon. `horizon-connect` —
небольшая программа, которая открывает его для обычного Minecraft 26.3, в обе стороны:

- **`join`**: игрок на обычном Minecraft заходит в мир друга в Horizon по его коду приглашения.
- **`host`**: игроки Horizon заходят на обычный сервер или в обычный мир, открытый для сети, по коду
  приглашения.

Ни одна из игр не меняется. Программа — это второй конец туннеля, собранный на том же крейте, что и в игре
(`horizon-friends`), поэтому коды, шифрование, проброс портов, STUN и релеи работают ровно так, как описано в
[play-with-friends.md](play-with-friends.md).

```
 join:  обычный клиент ──▶ 127.0.0.1:25565 horizon-connect ══ туннель ══▶ Horizon хоста ──▶ встроенный сервер
 host:  клиент Horizon ──▶ Join a friend  ══ туннель ══▶ horizon-connect ──▶ обычный сервер или LAN-мир
```

## Зайти к другу в Horizon с обычного Minecraft

Друг в Horizon открывает Play with Friends (меню паузы, Friends, Start Sharing) и присылает код. Затем:

```sh
horizon-connect join 2A7KQ-M3XPD-...
```

и в Minecraft 26.3: **Сетевая игра > Прямое подключение > `localhost`**. Мир виден в списке серверов как
обычный сервер. Каждое подключение, и пинг из списка серверов, и сам вход, получает свою сессию, так же как
клиент Horizon открывает отдельную сессию на каждое подключение. Не закрывайте программу, пока играете.

- `--port N` слушает `localhost:N` вместо 25565 (например, если там уже запущен сервер).
- `--relay ХОСТ:ПОРТ` нужен для короткого кода релея; полный код сам называет свой релей.
- Принимаются только подключения с этого компьютера: кто доберётся до порта, тот играет по коду.
- Если до мира друга не достучаться, причина (тот же текст, что показывает Horizon) появляется описанием
  сервера в списке серверов или на экране отключения при входе.

Встроенный сервер работает для друзей в офлайн-режиме ([Identity](play-with-friends.md#identity)), поэтому
игрок обычного Minecraft заходит под ником из своего лаунчера, без проверки аккаунта.

## Пустить игроков Horizon в обычный мир

Запустите обычный сервер 26.3 или откройте одиночный мир для сети (игра пишет порт в чат), затем:

```sh
horizon-connect host --server 127.0.0.1:25565
```

Программа печатает код приглашения; игроки Horizon вставляют его в **Join a friend** (или в Прямое
подключение). Enter останавливает раздачу: код перестаёт работать, прямой порт закрывается, проброс на роутере
удаляется.

- `--port N` — прямой порт (по умолчанию 25580, также `HORIZON_FRIENDS_PORT`).
- `--relay ХОСТ:ПОРТ` дополнительно регистрируется на релее: короткий код и запасной путь.
- `HORIZON_FRIENDS_UPNP=0` не трогает роутер, `HORIZON_STUN_SERVERS=none` отключает STUN,
  `HORIZON_FRIENDS_PATH=relay|direct` ограничивает путь, как в игре.
- Обычные LAN-миры проверяют аккаунты, как сервер в онлайн-режиме, поэтому игрок Horizon должен войти в
  аккаунт ([microsoft-account.md](microsoft-account.md)). Отдельный обычный сервер с `online-mode=false`
  пускает с любым ником.
- Друзья из интернета достучатся до хоста способами из раздела
  [When friends can't reach the host](play-with-friends.md#when-friends-cant-reach-the-host): UPnP, проброшенный
  порт, VPN вроде Tailscale (запустите его до `host`, чтобы код содержал его адрес) или релей.

## Сборка

```sh
cargo build --release -p horizon-connect
```

Программа — `target/release/horizon-connect` (`.exe` в Windows), около 1 МБ, без других файлов.

## Задержка

Туннель добавляет гораздо меньше миллисекунды. Время туда-обратно на одном компьютере (медиана из 300,
эхо-сервер за `host`, туннель, затем `join`):

| Сообщение | Напрямую | Через туннель |
| --- | ---: | ---: |
| 64 байта (движение, чат) | 0,03 мс | 0,07 мс |
| 4 КиБ (обновления блоков) | 0,03 мс | 0,09 мс |
| 64 КиБ (чанк) | 0,05 мс | 0,31 мс |

Открытие сессии (дозвон по адресам из кода и обмен ключами) на одном компьютере заняло 5–14 мс; через интернет
добавляется ещё несколько обменов между игроками. Это происходит один раз на подключение: при входе и при
каждом пинге из списка серверов, а не во время игры. Между двумя компьютерами задержка игры — это задержка
сети, как при любом прямом подключении; через релей — путь до релея и обратно.

## Версии

Обе стороны должны играть на 26.3: туннель передаёт протокол без изменений и не переводит его, поэтому клиент
другой версии получит от сервера его собственное сообщение о несовместимой версии.

## Проверка

- `crates/horizon-connect/tests/join.rs`: хост перед эхо-сервером, порт `join` перед его кодом и клиент,
  который говорит handshake, всё на одном компьютере. Вход доходит байт в байт (больше одного кадра туннеля
  игровых данных после handshake), каждый пинг из списка серверов получает свою сессию, а закончившийся код
  показывает причину в списке серверов (с ответом на пинг) и при отключении на входе.
- Вручную, оба конца сразу на одном компьютере: обычный сервер, `HORIZON_FRIENDS_UPNP=0
  HORIZON_STUN_SERVERS=none HORIZON_FRIENDS_LOOPBACK=1 horizon-connect host`, `horizon-connect join КОД
  --port 25570` и клиент на `localhost:25570`: пинг и вход получают по прямой сессии; вход, чанки и чат в обе
  стороны.
- С самим Horizon (nightly 2026-10-28): мир, открытый через Start Sharing, `horizon-connect join` с его кодом и
  клиент перед ним. Мир появился в списке серверов, игрок зашёл, его сообщение показалось в чате Horizon, и он
  играл 40 секунд (keep-alive отвечены, около 14 600 пакетов), после чего вышел.
